# Documentation guide

## Read by purpose

| Need | Document |
|---|---|
| Understand the submission and evidence | **[Final report](final_report.md)** |
| Check primary checkpoint/cohort numbers | **[CIC evidence ledger](cic_evidence.md)** |
| Inspect the separately fitted second-source model | **[ToN-IoT evaluation](ton_iot_evaluation.md)** and [machine-readable evidence](ton_iot_evidence.json) |
| Understand what remains unproven | **[Limitations](limitations.md)** |
| Run the code or open a saved demo | **[Reproduction and handoff](reproduction.md)** |
| Understand runtime contracts | **[Architecture](architecture.md)** |
| Investigate labels, duplicates, independent support | [Data quality](data_quality.md) |
| Inspect models/features/clean ablations | [Modeling](modeling.md) |
| Inspect label abstention, incidents, campaign failures, formative task | [Triage](triage.md) |
| Inspect drift and frozen external evaluation | [Monitoring and transfer](monitoring_and_transfer.md) |
| Trace decisions, commits, artifacts, and invariance | [Experiment registry](experiment_registry.md) |
| Read the pre-fit plans in English | [Protocols](protocols/README.md) |

The evidence JSON is generated by `python -m netirava ton-report --output docs/ton_iot_evidence.json` from saved decisions without scoring/fitting. It adds after-gate and global host-novelty interpretation; original evaluator files remain outside Git.

## Editorial decisions after content review

Names now describe purpose rather than reading order. Distinct evidence stays separate; overlapping narrative is merged. All current maintained documentation and user-facing text is English. Raw labels, checkpoint metadata, historical logs/results, and original protocol snapshots retain experimental provenance.

| Previous document(s) | Decision and current location | Reason |
|---|---|---|
| `01_problem_framing.md` + `08_final_report.md` | **Merge → [final_report.md](final_report.md)** | Problem/output definitions belong beside the final argument; avoid two competing summaries |
| `02_data_eda_labels.md` + cohort section of `11_ablation_and_cohorts.md` | **Merge → [data_quality.md](data_quality.md)** | Label quality, fingerprint conflicts, and cohort eligibility are one evidence chain |
| `03_preprocessing_features.md` + `04_modeling.md` + ablation section of `11_ablation_and_cohorts.md` | **Merge → [modeling.md](modeling.md)** | Compare feature/model treatments and negative results in one place |
